A bot that forecasts questions on [Metaculus](https://www.metaculus.com/) and competes in its
bot tournaments. For each question it gathers research from several sources, asks an ensemble of large
language models for forecasts, and publishes the median along with a comment showing
each model's reasoning. Originally forked from
[starter template](https://github.com/Metaculus/metac-bot-template), built on the
[forecasting-tools](https://github.com/Metaculus/forecasting-tools) framework, and it runs
unattended from GitHub Actions. 
Uses Asknews, OpenAI native search, Gemini native search, and a custom agentic gap-fill research pass.

## How it did

The bot competed as `nostreambot` in the Fall 2025+ FutureEval bot tournaments. 
As an example, in the Summer 2026 FutureEval Bot Tournament, Metaculus's
bots-only tournament series, which is what the default run mode below points at. On the
leaderboard as read on 2026-09-09, it ranked 15th of 277 entries
with about 3,240 spot peer points over 256 scored questions, above the all-bots ensemble average. 
The leader had about 4,820. For each question it compares the bot's forecast at
close with the other entrants' forecasts at the same moment, and a positive score means the bot
beat the field's average on that question.

The bot studies its misses with the postmortem tooling in `metaculus_bot/performance_analysis`,
which the repo calls residual analysis. After each batch of resolutions it pulls the scored
forecasts, buckets them by configuration era (the stretches between changes to the roster or
the pipeline), and traces the largest misses back to the research the bot read and the
reasoning it published. The recurring finding is that the worst misses come with all three
models agreeing on a shared briefing. `docs/performance_analysis.md` has the conventions, and
`FUTURE.md` records the decisions those rounds led to.

## How it works

Every question goes through the same pipeline, which lives in `metaculus_bot/forecaster.py`.

1. The bot reads the question's close time and grants itself a time budget. With enough time it
   runs everything below. With little time it takes a fast path that drops the slow optional
   research. A question that can't be published before it closes is skipped at intake.
2. Research runs in parallel. AskNews is the primary news source, and more sources run
   alongside it: OpenAI's native web search, Google's Gemini grounded search, financial data
   from yfinance and FRED (the St. Louis Fed's economic data service), and a snapshot of
   prediction-market prices from Polymarket, Kalshi, Manifold and PredictIt. A fetcher reads the
   pages the question names as its resolution source, and a numeric question that maps to a
   known data series gets a summary of that series' history as an anchor. Two gap-fill passes
   then look for facts the first round missed. In the first, a model lists the missing facts
   and a web search runs for each. In the second, a model searches, fetches and reads documents
   in a bounded loop until it has filled the gaps it listed. Each source has its own on/off
   flag.
3. Multiple models forecast independently from the same research. 
   The roster lives in `metaculus_bot/llm_configs.py` and
   changes as the vendors release new models. Each model writes its forecast in a structured
   block, and the bot reads the value back out, repairing or salvaging a malformed block before
   giving up on that model.
4. The published forecast is the median of the three. For numeric and date questions the bot
   converts each model's percentiles to a full probability distribution first and takes the
   median pointwise. A stacker, a model that rewrites the forecast when the three disagree, is
   in the code but off in production. In an 88-question test it scored no better than the
   median.
5. A gate checks the question is still open, then the forecast and the comment go to the
   platform.

The bot can also forecast Mantic's Crucible competition (competitions.mantic.com), a fork of the
Metaculus platform with the same API, by swapping in a different platform client.
`docs/architecture.md` walks the pipeline stage by stage and names the module behind each one.

## Running it

You need Python 3.12 or newer and [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/No-Stream/metaculus-bot.git
cd metaculus-bot
uv sync --dev          # or: make install
cp .env.template .env  # then fill in your credentials
```

`.env.template` documents every setting. A Metaculus API token is required, and the models run
through an OpenRouter account. Each research source is off until you set its flag and add its
credentials (AskNews, Google AI Studio for Gemini search, FRED for financial data), and the
production workflows turn all of them on. Run every command through `uv run`, which uses the
project's own virtual environment, so there's nothing to activate.

These commands are free. The test suite blocks all network access, so it needs no credentials.

```bash
make test        # full pytest suite
make lint        # ruff check
make typecheck   # basedpyright
make format      # ruff format + autofix
```

Everything below costs money. A live run calls every model and research source for each new
question, about $2.60 per question in API credits, and publishes the result to the platform. A
backtest replays already-resolved questions and scores the bot against the actual outcomes. It
spends the same credits per question and publishes nothing.

`--mode tournament`, the default, forecasts the current FutureEval bot tournament.
`metaculus_cup` forecasts the Metaculus Cup, `minibench` forecasts Metaculus's MiniBench
question set, `mantic` forecasts the Crucible competition, and `test_questions` runs a fixed
handful of example questions. `--only-posts` narrows a run to the listed post ids. The Mantic
mode needs `MANTIC_TOKEN`, and `make run_mantic` and `make run_mantic_one POST=<id>` wrap it.
The bot can also spend OpenRouter credits that Metaculus donates to tournament entrants, through
a second account, and a Mantic run refuses to start unless `DONATED_OPENROUTER_KEY_ENABLED=false`,
so donated credits are never spent outside Metaculus.

```bash
make run                                                    # --mode tournament
uv run python main.py --mode metaculus_cup
uv run python main.py --mode tournament --only-posts 12345
make backtest_smoke_test   # 4 questions; backtest_small, _medium and _large run 12, 32 and 100
```

In production the bot runs from GitHub Actions, with the credentials in repository secrets. The
`.github/workflows/` directory holds one workflow per competition (`run_bot_on_tournament.yaml`,
`run_bot_on_metaculus_cup.yaml`, `run_bot_on_minibench.yaml`, `run_bot_on_mantic.yaml`), each
on an hourly cron, plus two manual test workflows and the CI check. GitHub's cron is unreliable
for this repository: it delivered only about 22% of the scheduled firings between 2026-08-27
and 2026-09-07, with gaps of several hours. So an external scheduler (cron-job.org) also
triggers the workflows twice an hour through GitHub's workflow-dispatch API, which is safe
because a run that finds no new question spends nothing. `make dispatch_watch` shows how many
runs arrived each day, and `make cronjob_dispatch_setup` prints the dispatcher jobs it would
create. `docs/operations.md` covers the workflows, the credentials and the cost rules in full.
